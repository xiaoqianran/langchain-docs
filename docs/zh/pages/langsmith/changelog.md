## 亮点

* **所有工作区的新侧边栏**：新侧边栏现在出现在每个工作区中并取代旧侧边栏。侧边栏顶部的组织和工作区菜单取代了 LangSmith 字标和产品切换器，因此您可以从一个位置切换组织和工作区。自定义字标徽标不再出现在侧边栏中；上传自定义组织头像以对其进行品牌化。 [Learn more](/langsmith/navigate-agents)。
* **使用引用\_outputs 创建示例**：API 以及 Python、JavaScript、Go 和 Java SDK 现在使用 `reference_outputs` 在您创建示例（包括批量创建示例）时设置预期输出。 `outputs` 仍可用作已弃用的别名，但在同一请求中同时发送 `reference_outputs` 和 `outputs` 会被拒绝。现有代码继续工作，响应、更新和分段上传仍然使用`outputs`。 [Learn more](/langsmith/manage-datasets-programmatically)。* **存储拒绝不明确的命名空间标签**：图表中的存储操作现在拒绝空或包含 `.` 的命名空间标签，与 HTTP 存储 API 已应用的规则相同。以前，诸如 `"tenant.bob"` 之类的标签与命名空间 `("tenant", "bob")` 处理相同的项目，因此从不受信任的输入构建命名空间的图形代码可以读取、覆盖或删除另一个命名空间的项目。此类调用现在会返回无效输入错误，代理服务器 0.16.2 和 0.15.5 中也已修复此问题。 [Learn more](/langsmith/agent-server-changelog)。
* **组织范围内的批量导出创建限制**：LangSmith 除了现有的每个工作区限制之外，云现在还限制组织中所有工作区的批量导出创建：默认情况下，每个组织每小时 1,000 个创建和 1,000 个活动计划。当组织超出限制时，`create_bulk_export` 返回 429 响应，并使用 `Retry-After` 标头表示每小时限制。现有计划自动创建的导出不计入每小时总数，因此运行计划永远不会被阻止。 [Learn more](/langsmith/data-export)。

## 追踪* `langsmith` CLI 现在包括 `threads query`、`threads stats`、`threads aggregate-stats`、`threads share`、`traces query`、`runs create`、`runs ingest-batch`、`runs get-url`、`runs share`、 `public runs retrieve` 和 `public runs query`，因此您可以搜索线程和跟踪、编写运行并共享它们，而无需直接调用 API。
* 过滤运行树现在在活动过滤器下方有一个 **完整树** 或 **仅匹配** 开关，因此您可以保持完整跟踪层次结构可见，并突出显示匹配运行。仅匹配仍为默认值。
* 您的跟踪工具提示和线程摘要现在显示基于缓存读取令牌作为输入令牌的份额的**缓存命中率**，并且线程摘要将其显示为百分比。当您的模型报告零缓存读取时，缓存命中率显示为 0%，而当未报告使用情况时，缓存命中率会隐藏。
* 轨迹现在会保留您在 URL 中的阅读位置：重新加载或共享线程链接会在您正在阅读的转弯处打开消息并运行，并且“详细信息”上的“返回轨迹”按钮可让您返回到该消息。
* 当跟踪存储繁忙时，批量导出分区不再在几分钟内失败。被拒绝的分区现在会等待并再次运行长达 2 小时，而不会耗尽重试次数。* 现在，您可以在运行中打开 **共享** 菜单，然后选择 **复制 URL** 将链接复制到当前视图，而无需公开运行。
* 现在，您可以通过将 `min_feedback_modified_at` 和 `max_feedback_modified_at` 传递到 `POST /v2/traces/query`（`/v2/runs/query` 已经支持的反馈窗口）来根据反馈修改时间来过滤跟踪。该界限适用于`trace_filter`或`tree_filter`中的反馈条件，因此每个请求必须至少包含一个反馈条件，例如`eq(feedback_key, "correctness")`。
* 现在，您可以通过发送 `metrics` 数组而不是 `metric`，在一次调用 `/v2/runs/analytics` 中请求最多 10 个令牌和成本字段的总和、平均值、最小值、最大值或百分位数聚合，因此您不再需要为每个指标运行一次相同的查询。
* LangSmith MCP `query_runs` 和 `fetch_runs` 工具现在默认返回 `app_path`，因此代理可以直接链接到 LangSmith UI 中的规范运行页面，而不是从运行 ID 构建跟踪 URL。
* 现在，您可以拖动表格列标题对列重新排序，并且顺序会保存在每个浏览器中的每个表格中。将鼠标悬停或聚焦标题以显示其左侧的夹点，或使用列菜单中的**向左移动**和**向右移动**。* 全局搜索现在允许您使用搜索页脚中新的 **按当前代理过滤** 切换来搜索所有代理，并且在按代理过滤时包含沙箱。
* 代理注册表 CRUD 现在可在 Go、Java、JavaScript 和 Python SDK 中使用，因此您可以使用类型化对象和 `client.agents` 服务创建、检索、列出、更新和删除代理。
* 使用 Python、JavaScript、Go 或 Java SDK 创建代理不再需要 `source_type`；如果省略，它现在默认为 `EXTERNAL`，因此您的端点托管代理无需额外配置即可注册。
* 您可以要求显式创建代理以在工作区中进行跟踪，因此跟踪和跟踪项目不再隐式创建代理；仅将痕迹发送给您在 `POST /api/v1/agents` 注册的代理。工作区管理员可以使用工作区设置 API 中的 `require_explicit_agent_creation_for_tracing` 字段打开此功能，并且从跟踪创建代理的请求将被拒绝并显示 403 错误。* 代理现在记录所有者：新代理将分配给创建它们的用户，并且所有者显示在“所有代理”表的 **所有者** 列和代理概述页面上。工作区管理员可以从代理操作菜单中更改所有者，并且 `PATCH /api/v1/agents/{agent_id}` 上的 `owner_id` 字段可以设置或清除它。

## 提示和游乐场

* LangSmith Chat 的模型选择器现在提供 Sonnet 5.5、Opus 5.5、GPT-6.1 Sol、GPT-6 Luna 和 Gemini 3.8 Flash，Sonnet 5.5 是新聊天的默认版本。 Sonnet 5、Haiku 4.5 和 GPT-5.6 Terra 已从选择器中删除，您保存的模型配置仍然有效。

＃＃ 反馈* 反馈现在可以通过新的 `feedback_config_id` 字段记录其写入的反馈配置的 ID，并且服务器会拒绝不属于工作区中相同反馈键的 ID。
* 您现在可以使用 `langsmith feedback retrieve`、`langsmith feedback update`、`langsmith feedback delete`、`langsmith feedback tokens create`、`langsmith feedback tokens update` 和 `langsmith feedback configs delete` 读取、编辑和删除运行反馈、创建和更新反馈令牌以及删除反馈配置。已弃用的 `langsmith feedback "<note>"` 别名已删除，因此请使用 `langsmith report` 提交注释，并使用 `langsmith feedback` 管理现有反馈。
* 创建反馈标签现在会拒绝已在同一位置使用的键，例如队列标题、队列审核视图或运行的反馈，并显示消息“此反馈标签已在此处使用”。队列也不能使用列出相同键两次的标题来保存。
* 您可以使用 `isEnforced` 或 `is_enforced` 从 JS 和 Python SDK 创建密钥的强制反馈配置，这需要工作区管理员拥有 `feedback-configs:manage-enforced` 权限。创建配置不再改变键的乐谱方向，除非您通过`isLowerScoreBetter`或`is_lower_score_better`。* 通过 JS SDK 使用 `traceId` 创建的反馈现在会与您的运行一起批处理并在后台发送，因此 `createFeedback` 会立即返回。拨打`awaitPendingTraceBatches()`等待送货； `extendTraceRetention: false`的反馈仍然直接发布到`/feedback`。

## 数据集和实验

* `langsmith` CLI 现在包括用于比较实验、数据集共享、分割、克隆和版本标记的命令。运行 `langsmith datasets retrieve-version` 按时间或标签读取版本，运行 `langsmith datasets versions retrieve-diff` 比较两个版本，运行 `langsmith datasets update-tags` 将标签移动到版本。
* 现在，您可以通过将 `exclude_default_fields=true` 传递到 `GET /api/v1/examples` 并结合 `select` 来列出仅包含您选择的字段的示例，以便 `select=id` 仅返回示例 ID，而无需输入或其他默认字段。当省略该标志时，默认响应不变。 Python、JavaScript 和 Go SDK 通过 `list_examples`、`listExamples` 和 `ExampleListParams` 公开了这一点。

## 评估者* 轨迹评估者现在可以对每个对话的缩短版本进行评分。打开评估器编辑器中轨迹源下的 **Compacted** 开关，评估器在运行和测试时都会收到缩短的消息。
* 您的 TypeSafe 和 TypeSafe 兼容评估器现在可以从模型配置中的 **Extra Headers** 字段发送额外的请求标头，例如 `TypeSafe-Danger-Zone-Long-Context`。以前达到上下文限制的长线程现在可以在启用 beta 长上下文选项的情况下进行评分。
* 沙箱评估器**测试**结果现在在可扩展的错误详细信息中显示完整的评估器回溯，因此您可以看到哪个评估器函数和行失败。超过 64 KiB 的回溯在中间被缩短并标记为已截断。
* 您现在可以使用 `langsmith online-evaluators create`、`update` 和 `spend` 从 `langsmith` CLI 创建、更新和检查在线评估者的支出。通过 `langsmith evaluator list`、`get` 和 `delete` 仍然可以列出、读取和删除求值器。

## 部署* 您的审核表单现在显示用于人机循环中断的决策选择器，因此您可以选择批准、编辑、拒绝或响应，并仅填写该决策的字段，并且单决策中断不再让您手动键入决策类型。聊天中的每次调用工具批准使用相同的批准、编辑、拒绝和响应卡，一次调用一个工具调用，长的决策描述在“显示更多”按钮后面开始缩短。
* `GET`和`POST /threads/{thread_id}/history`现在接受`select`参数，该参数仅返回每个状态的命名字段，例如`tasks`或`checkpoint`，或状态值的单个键，例如`values.messages`。未知字段和没有键的 `values.` 会返回 422 错误，因此您可以请求客户端从每个历史记录条目中读取的内容。
* Studio 的右侧交互和跟踪面板现在可以通过 **隐藏侧面板** 隐藏，并通过 **显示侧面板** 再次显示，并且当您在图表和聊天之间切换或重新加载页面时，它会保持隐藏状态。显示它会恢复您之前的宽度。
* Studio 聊天首先列出您最近更新的线程，因此当运行开始或结束时，线程会移至顶部，而不是停留在列表底部。* 不使用 `trace_storage` 值创建的新 AWS 数据平面现在将跟踪存储在 SmithDB 而不是 ClickHouse 中。要保持 ClickHouse 默认值，请在 `POST /orgs/current/data-planes` 请求中将 `trace_storage` 设置为 `CLICKHOUSE`。现有数据平面保留其当前的跟踪存储。
* 现在，对于每个 MCP 协议修订版中您的 CORS 设置不允许使用 `Origin` 标头的请求，MCP 端点都会返回 HTTP 403，从而阻止 DNS 重新绑定攻击。 `http://localhost` 等环回源仍然允许，因此请在 `CORS_ALLOW_ORIGINS` 或 `CORS_CONFIG` 中列出基于浏览器的 MCP 客户端的源。
* 现在，您可以使用新的终止开关立即停止部署上的每个正在进行的运行，默认情况下，工作区管理员和具有 `deployments:cancel-runs` 权限的自定义角色可以使用该开关。按“停止”将返回操作的进度并持续更新，直到所有目标运行都停止，并且在页面重新加载后最新的操作仍然可见。
* JS 图现在可以通过将 `langgraph_api:url` 上下文变量作为 `apiUrl` 传递，使用 SDK 客户端调用自己的部署，包括在自定义身份验证下，其中调用以开始运行的用户身份运行。* 现在，当您使用 **使用现有 IAM 角色** 创建 AWS 数据平面时，您可以输入自定义 IAM 角色名称和自定义 Karpenter 实例配置文件名称，以便数据平面使用 BYOIAM Terraform 模块输出中的名称。在**高级设置**下设置它们，并且仅当`byoiam.is_enabled`为`true`时才接受名称。
* 托管 Deep Agents 现已在 AWS BYOC 数据平面上启用，并且 `/api/v1/triggers` 和 `/api/v1/channels` 下的触发器和通道端点将路由到触发器服务器，因此您的通道和触发器请求可以到达该服务器，并且代理修订可以通过公共数据平面 URL 读取 Context Hub。
* Azure 上的生产部署现在拥有自己的私有托管 PostgreSQL 数据库，该数据库会在每次部署时自动配置，并且您可以在更改数据库层时调整其大小。
* **监控**选项卡中的部署指标图表现在加载到 Azure 部署上，显示部署的 CPU、内存、重新启动、副本、请求、延迟和运行队列。超过 32 天的 Azure 指标请求将缩短至最近 32 天。* Azure BYOC 数据平面现在通过 Azure 专用链接到达LangSmith 控制平面，因此您的数据平面将其 API 和检测信号流量发送到 VNet 内的专用终结点，同时您的应用程序保持相同的主机名。 LangSmith 自动批准端点连接，HTTPS 请求可能会失败或超时，直到批准完成。
* 您的 Azure BYOC Redis 连接现在验证集群分片的证书主机名，因此 Redis 启动不再依赖于跳过该检查。
* 具有一个数据库和身份验证以及 BYOC 数据平面的自托管安装现在可以自动将现有跟踪项目和实验迁移到代理平台代理。迁移将保持关闭状态，直到您将 `AGENT_PLATFORM_MIGRATION_ROLLOUT_ENABLED` 设置为 `true`，并且每个 BYOC 工作区在经过验证后会向控制平面报告准备情况。
* 私有模式下的 AWS BYOC 数据平面现在可以通过将 `spec.ingress.customerManagedDns` 设置为 `true` 来跳过 Route53 私有托管区域和 apex 记录，这需要 BYO VPC。将您自己的 DNS 指向内部 NLB 的入口主机名，并且您的数据平面就绪状态将不会等待 Route53 记录。* 捆绑操作员上的自托管部署现在可以通过部署设置管理额外的 ServiceAccounts 和 SecretProviderClasses，并使用 YAML/JSON 编辑器和 SecretProviderClasses 的 Secret 挂载路径。
* 当设置`LANGGRAPH_THREAD_HISTORY_MAX_STATE_BYTES`时，线程历史记录响应现在受到大小限制：历史记录返回最新状态并在超出限制的条目之前停止，因此大线程不再产生过大的响应。该变量默认关闭。
* 队列工作线程现在可以在可以启动的运行上进行扩展：队列自动缩放程序对正在运行的运行进行计数，加上每个线程在 10 分钟内到期且没有任何运行的待处理运行，因此在其线程上正在运行的运行后面等待的运行不再添加队列 Pod。
* 使用 `langgraph dev` 的本地运行不再向 LangSmith 报告使用情况，因此不再按自托管费率计费。从已发布的映像构建的部署会像以前一样继续报告。

＃＃ 引擎* 现在，您可以使用服务帐户令牌在 **设置 > GitLab** 中连接 GitLab 实例，然后将 GitLab 项目与 GitHub 存储库一起添加到引擎板。扫描、修复和合并请求审查适用于 GitLab 项目，合并修复的合并请求即可完成其问题。

## 网关

* 模型后备链现在接受可选的 `ejection` 块以及 `failure_threshold` 和 `cooldown_seconds`。当候选者在窗口内失败链的触发条件达到阈值次数时，您的网关会在冷却期内跳过该候选者并移至下一个候选者，因此重复的提供者失败不再减慢每个请求。
* 现在，您可以使用工作区 **DEEPINFRA\_API\_KEY** 通过 LLM 网关将请求路由到 Deep Infra，使用`/deepinfra/v1/chat/completions` 的聊天完成或`/deepinfra/v1/messages` 的Anthropic 消息，并将 Deep Infra 设置为后备提供商。
* 您的“使用情况”选项卡现在可以通过“细分依据”中的新“自定义维度”选项按任何 `X-Gateway-*` 标头细分支出，默认为 `X-Gateway-Service`，无需支出政策即可使用。更改标题名称会更新图表和 URL，因此共享链接保持相同的分组。* 使用部署的服务密钥（包括预览部署）进行身份验证的 LLM 网关请求现在包括请求元数据和网关跟踪中部署绑定到的代理和环境，因此您可以按代理过滤网关策略和跟踪。
* 单个请求的网关跟踪现在共享一个`gateway.request.id`，并且每次尝试都会记录其在回退链中的位置、提供程序调用之前的网关开销以及失败的回退所花费的时间，因此您可以对请求的尝试进行分组并查看其延迟的去向。
* 超出每月跟踪限制的网关跟踪现在将不包含其内容而存储，而不是被拒绝，并且跟踪元数据包括 `content_quota_exceeded: true`，以便您可以识别它们。
* 现在，您可以通过统一的 `/v1/systemone` 端点调用 OpenAI 决策模型，方法是将 `model` 设置为 `openai/gpt-6-luna`，使用 OpenAI 的原生决策请求和响应格式，无需翻译。* 对 Anthropic 和 OpenAI 的 BYOK 调用的跟踪现在包括一个 `provider_key_hint` 元数据字段，该字段显示密钥的编辑形式，因此您可以将每个跟踪与发出调用的密钥进行匹配，并将其与供应商账单进行协调。对其他提供程序的调用和对自定义端点的调用不会记录提示。
* 您现在可以注册私有 MCP 服务器并从中构建只有您可以查看和使用的个人工具包。添加 MCP 服务器或创建工具包时选择“**个人**”，并在“**工具**”下的“用户”选项卡上找到它们。
* 工作区管理员现在可以通过将 `owned_by=any` 传递到 `GET /v1/managed-tools/servers` 来列出每个成员的个人 MCP 服务器，每个服务器都显示其所有者。调用它的成员会收到 403 响应。
* 新工具包默认为 **使用连接的工具**，因此包含配置文件中的服务器和您添加的服务器的工具包会从连接的服务器返回工具，而不会在缺少一个凭据时导致发现失败。

## 沙箱

* 可写 S3 装载现在可以通过将 `encryption.kms_key` 设置为装载区域中的 KMS 密钥 ARN，使用客户管理的 KMS 密钥加密上传。上传到默认加密为 SSE-KMS 的存储桶现在也会保留，而不是在写入成功后被删除。
* 沙盒命令历史记录现已在亚太地区、欧盟和美国 GCP 生产区域启用，因此您可以从沙盒命令查看保留的 stdout 和 stderr，包括在 Box 停止之后。
* 沙箱现在可以使用短期工作负载身份（而不是静态密钥）向 AWS、GCP 和 Azure 进行身份验证：设置 `aws.role_arn`、`gcp.workload_identity_provider` 或带有 `tenant_id` 和 `client_id` 的 `azure` 代理规则，并且出口代理将云凭证添加到请求中，以便沙箱永远不会保存它们。 Azure Blob 存储也可用作 `azure_blob` 安装类型。* 正在运行的沙箱现在可以从耗尽的主机上实时迁移，暂停时间仅为数十毫秒，而不是在另一台主机上挂起并唤醒。
* 当主机内存不足时，BYOC 数据平面上的沙箱不再一起停止。沙箱现在可以使用完整节点。现有的 BYOC 数据平面保持其当前限制，直到其配置更新。
* 沙箱现在可供 Azure 生产组织使用，让您可以创建、运行、停止、恢复和删除沙箱，并在 `*.azure.smithbox.dev` 打开其服务 URL。报告沙箱计算和存储使用情况以进行计费。

## 追踪* 所有代理页面现在在可排序表中显示代理，其中包含名称、最近运行、创建时间、跟踪计数、总成本、错误率、延迟、令牌和代理 ID 列；现在，跟踪计数、总成本和总令牌在所有环境中求和，并且新的“关于这些指标”工具提示解释了哪些列使用最近活动的环境。

* 只要查询包含反馈条件，API 中的运行和跟踪查询现在接受 `min_feedback_modified_at` 和 `max_feedback_modified_at` 来按反馈的上次修改时间进行过滤。在无法应用这些边界的部署上使用这些边界的请求将返回 501 错误，而不是忽略这些边界。* 跟踪消息现在在组元数据中包含每个 LLM 调用的提示缓存细分，因此您可以在每次调用时查看提示是从缓存读取还是写入缓存，包括`token_usage.input_token_details` 和 `cost.prompt_cost_details` 下的缓存 TTL。
* 长过滤器查询现在可以跨多行换行。当查询溢出过滤器栏时，会出现一个新的 **包裹过滤器** 按钮，并且每个项目和运行详细信息视图都会记住您的选择。默认情况下，换行处于关闭状态。
* 现在，您可以通过将 `rank_groups_by` 设置为 `total_cost`，按总成本对分组指标结果进行排名，因此，当查询返回的组数量多于 `limit` 时，将保留成本最高的组。默认仍然是运行计数。此选项适用于**名称**、**运行类型**、**标记**和**元数据**分组，但不支持**项目**或**反馈**分组。
* OpenTelemetry GenAI 跨度的缓存输入令牌现在按缓存速率而不是完整输入速率进行计数。现在读取使用点键 `gen_ai.usage.cache_read.input_tokens` 和 `gen_ai.usage.cache_write.input_tokens` 发送的跨度，并且现在记录作为 `gen_ai.usage.reasoning.output_tokens` 发送的推理令牌。* 仪表板比率 KPI 图表现在包含 **显示为百分比** 选项，因此每个反馈 0.16 次运行之类的值可以显示为 16%。小数显示保留默认值，并且在编辑图表时会保存您的选择。
* 现在，您可以使用`GET /api/v1/agents`上的`sort_by`和`sort_order`查询参数按`name`、`last_run_start_time`或`created_at`升序或降序对代理列表进行排序。代理响应还包含 `created_at` 时间戳。
* 您现在可以从代理概述页面上的**代理设置**菜单重命名代理，新名称会立即显示在代理详细信息和代理列表中。
* 您现在可以从“构建/连接”菜单启动新代理：**+ 代理**、代理切换器的 **+** 和 **创建新代理** 磁贴均会打开同一菜单，并提供构建（无代码、带代码）和连接（跟踪现有代理）选项。

## 部署

* MCP 工具结果现在以有效的 JSON 形式返回，而不是 Python repr() 文本，失败的运行包含完整的错误消息，而暂停以进行人工输入的工具会返回显式错误，而不是看起来成功。
* 现在可以通过 Azure 控制平面上的 API 创建和删除 Azure 数据平面。创建 Azure 数据平面需要资源组 ID 和 Entra 租户 ID，并在协调器应用数据平面时返回 202。当 Azure 数据平面仍在预配时，也可以删除它。

* 一旦管理员配置了推送角色，使用 `langgraph deploy` 构建的本地映像现在可以在 LangSmith AWS 部署上运行。推送到单独的每个部署 ECR 存储库。这需要更新的LangGraph CLI，并且服务器会告诉旧客户端进行升级。
* 重命名部署将跟踪发送到的跟踪项目现在会返回 409 错误，因此部署跟踪保留在一个项目中。仅在分离或重新部署部署后才重命名项目。* 无服务器 M 和 L 部署现在运行单个副本，与无服务器 S 层匹配，因此计划摘要中显示的副本计数是您的部署实际使用的计数。
* 您现在可以创建一个仅在 SmithDB 中运行存储和查询的 AWS 数据平面，无需 ClickHouse。调用`POST /orgs/current/data-planes`时，将`trace_storage`设置为`SMITHDB`；默认值仍然是`CLICKHOUSE`。现有数据平面保留ClickHouse，尚不支持在现有数据平面上关闭它。
* 自托管部署现在可以将 CPU 自动缩放目标设置为容器 CPU 限制的百分比，关闭 API 服务器和队列的 CPU 缩放或 CPU 限制，并在容器规范编辑器和 API 中配置自动缩放器的扩展和缩小行为。
* Studio 聊天选项卡中的子代理调用现在会显示一张实时卡片，其中包含子代理的名称、任务、状态及其当前正在运行的工具，并且展开调用会在其参数和结果之前显示子代理的对话。
* 运行现在会忽略在 `config.configurable`、`context` 或 `checkpoint` 中发送的 `cron_id`，因此只有由 cron 触发的运行才带有 `cron_id`。

> * 修复了读取事件失败时 v2 线程事件流静默结束的问题：SSE 流和 WebSocket 现在在关闭之前发送带有未知\_错误代码的最终错误帧，以便客户端可以区分失败的流和空闲的流。
