# LangSmith 引擎问题类别

当 [LangSmith Engine](/langsmith/engine) 检测到跟踪中重复出现的问题时，它会用类别标记该问题。此页面列出了引擎分配的每个类别，以及每个类别的描述和具体示例。引擎会自动扫描您的痕迹，并为每个检测到的问题分配最合适的类别。

此页面上的 16 个类别涵盖了 Engine 观察到的最常见的代理故障模式。如果引擎分配的类别与实际问题不匹配，您可以将该问题标记为忽略并给出原因。引擎使用此反馈来改进其未来的分析。有关更多信息，请参阅[Close or reopen an issue](/langsmith/engine#close-or-reopen-an-issue)。

<Note>
当问题分类发生变化时，LangSmith不会发送通知。要随时了解功能更新，请观看 [LangSmith Cloud changelog](/langsmith/changelog) 或联系 LangSmith 支持。
</Note>

## 代理循环

代理在单个跟踪中多次重复相同的操作，但没有朝着用户的目标取得进展。

**示例：** 客服人员连续八次使用相同的查询调用相同的搜索工具，每次调用都返回相同的结果，而不使用结果来推进对话。

## 上下文爆炸由于无限制的上下文累积，而不是循环，跟踪消耗了大量令牌。

**示例：** 多轮对话会重播每个 LLM 调用之前消息的完整历史记录，导致令牌计数随着每个轮次而增长，即使代理没有重复操作也是如此。

## 错误恢复失败

工具返回显式错误，代理使用相同或几乎相同的参数重复重试相同的调用，而不是调整其方法。

**示例：** API 调用失败并出现 500 错误，代理连续重试完全相同的调用五次，而无需更改参数或尝试不同的工具。

## 功能差距

用户要求提供尚不存在的合法范围内功能。这是未满足的产品需求，而不是代理执行错误。

**示例：** 用户反复要求将报告导出为 PDF，但应用程序没有导出功能。代理正确地解释了限制，但反复出现的请求揭示了团队需要评估的未满足的产品需求。

## 有缺陷的计划代理的方法显示出对任务的根本误解。答案解决的问题与提出的问题不同，或者计划从第一次工具调用开始就是错误的。

**示例：** 用户要求计算每月平均值，但代理将所有值相加并报告总数，从而解决了与请求不同的问题。

## 护栏绕行

用户通过多轮转向或提示注入操纵代理生成超出其预期范围的内容。

**示例：** 用户逐步引导金融机器人从合法的账户问题转向生成机器人无权提供的具体投资建议。

## 幻觉

代理的响应包含任何工具输出中都不存在的特定事实、数字或名称。

**示例：** 当没有工具返回该数字时，代理报告“您的帐户余额为 4,200 美元”，这意味着代理捏造了该数字。

## 工具参数不正确

代理选择了正确的工具，但调用它时使用的参数与用户的意图或工具的架构不匹配。**示例：** 用户请求订单#12345，但代理使用截断的 ID“1234”或捏造的 ID 调用获取订单工具，返回错误记录或空结果。

## 能力意识缺失

代理试图使用它没有的工具，拒绝它可以处理的任务，或者遇到提示从未准备好的情况。

**示例：** 代理告诉用户“我无法搜索知识库”，即使其工具集中有搜索工具。

## PII 泄露

代理的响应包含敏感数据，例如社会安全号码、出生日期、家庭住址、电话号码、电子邮件地址或 API 密钥。引擎根据敏感数据的来源进一步对 PII 泄漏进行分类，因为每种泄漏的正确修复方法都不同：代理引入（代理自行生成敏感数据）、工具返回的回显（工具响应包含开发人员可以在源处过滤的敏感字段）或用户提供的回显（敏感数据已在用户的输入中）。

**示例：** 客户查找工具返回完整的用户个人资料，包括 SSN 和家庭地址，并且代理在对用户的响应中包含所有这些字段。## 响应截断

特工的响应在句子中间或代码块中间被切断。

**示例：** 代理的回答突然以“要解决此问题，您需要更新配置文件”结束，并且用户必须要求代理继续。

## 无提示工具错误

工具返回错误消息作为其内容，而不是引发异常，因此代理将错误视为有效响应。

**示例：** 搜索工具返回“404 Not Found”作为其结果内容，并且代理在对用户的响应中包含该错误文本，就好像它是真正的答案一样。

## 系统提示漂移

该代理没有拒绝，而是回答了一个超出申请目的的题外话问题。

**示例：** 当询问“给我写一首关于猫的诗”时，电子商务商店的客户支持机器人会编写 Python 脚本，而不是将用户重定向到适当的渠道。

## 任务逃避

代理在工作完成之前就宣布成功，简化任务以避免困难的部分，或者在一次失败后放弃而不尝试其他方法。**示例：** 用户要求对三个数据源进行详细分析，但代理仅从一个数据源生成一句话摘要并声明任务已完成。

## 追踪质量

该项目的痕迹缺少解锁 LangSmith 功能的元数据、标签或结构标记。这不是代理的行为问题，而是仪器差距。

**示例：** 跟踪在元数据中缺少 `thread_id`，因此线程视图无法对对话回合进行分组，并且 LLM 运行缺少模型提供程序元数据，因此成本跟踪显示空值。

## 错误的工具

存在一种更适合的工具，但代理针对用户的请求选择了错误的工具。

**示例：** 用户要求按 ID 查找单个订单，但代理调用“列出所有订单”工具而不是“按 ID 获取订单”工具，返回一页结果，但没有直接回答问题。
