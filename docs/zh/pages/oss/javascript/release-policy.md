# 发布策略

本页面解释LangChain和LangGraph的发布政策。单击下面的选项卡可查看每个选项卡的发布策略：

<Tabs>
  <Tab title="LangChain">
    LangChain生态由不同的组件包组成（如`@langchain/core`、`langchain`、合作伙伴包等）

    ## 发布节奏

    随着LangChain 1.0的发布，`langchain`和`@langchain/core`的**小**版本（例如，从`1.0.x`到`1.1.0`）遵循语义版本控制，并且可能会频繁发布。次要版本包含新功能和改进，但不包括重大更改。

    补丁版本经常发布，每周最多发布几次，因为它们包含错误修复和细微改进。

    ## API稳定性

    LLM 应用程序的开发是一个快速发展的领域，我们不断向用户和社区学习。因此，我们预计`langchain`和`@langchain/core`中的API将继续发展，以更好地满足用户的需求。

    随着LangChain 1.0采用语义版本控制：* 对公共 API 的重大更改只会发生在主要版本发布中（例如，`2.0.0`）
    * 小版本升级（例如，`1.0.0` 到 `1.1.0`）添加新功能而不破坏更改
    * 补丁版本升级（例如，`1.0.0` 到 `1.0.1`）包含错误修复和细微改进

    我们通常会尽力避免进行不必要的更改，并对正在删除的功能提供弃用政策。

    ### 其他包的稳定性

    LangChain生态中其他包的稳定性可能会有所不同：

    * **LangChain维护的合作伙伴包（如`langchain-openai`和`langchain-anthropic`）遵循语义版本控制，预计在1.0后保持稳定。其他合作伙伴软件包可能遵循不同的稳定性和版本控制策略，用户应参阅这些软件包的文档以获取更多信息。

    ## 弃用政策

    我们通常会避免弃用功能，直到有更好的替代方案可用。通过 LangChain 1.0 的语义版本控制方法，已弃用的功能将在整个 1.x 版本系列中继续有效。重大更改（包括删除已弃用的功能）只会发生在主要版本版本（例如 2.0）中。

    当某个功能在 `langchain` 或 `@langchain/core` 中被弃用时，我们将：

    * 在代码和文档中明确将其标记为已弃用
    * 提供推荐替代方案的迁移指导
    * 通过所有 1.x 次要版本为已弃用的功能提供安全更新

    在某些情况下，如果不推荐使用的功能不会引起维护问题，我们可能会允许它们在代码库中保留更长时间，以进一步减轻用户的负担。

    ## 长期支持 (LTS)

    LangChain遵循长期支持（LTS）政策，为生产应用提供稳定性：

    ### 发布状态定义

    包裹标记有以下状态之一：

    * **ACTIVE**：当前正在积极开发，包括错误修复、安全补丁和新功能
    * **维护**：接收所有安全补丁和关键错误修复，但没有新功能

    ### 当前 LTS 版本**LangChain 1.0** 被指定为 LTS 版本：

    * **状态**：2.0 发布之前一直有效
    * **支持期限**：2.0发布后，1.0将进入MAINTENANCE模式至少1年
    * **Semver 合规性**：用户可以在次要版本（例如 1.0 到 1.1）之间升级，而无需进行重大更改

    ### 旧版本支持

    **LangChain0.3**：

    * **状态**：维护模式
    * **支持期**：截至 2026 年 12 月
    * **支持包括**：安全补丁和关键错误修复
  </Tab>

  <Tab title="LangGraph">
    LangGraph遵循结构化的发布策略，以确保用户构建生产应用程序的稳定性和可预测性。

    ## 发布节奏

    我们预计**主要**版本间隔至少 6-12 个月，以便为生产应用程序提供稳定性。

    **次要**版本通常每 1-2 个月发布一次，其中包含新功能和改进。

    **补丁**版本根据需要发布，通常每周发布，以解决错误和安全问题。

    ## API稳定性

    ### 稳定的 API所有没有特殊前缀的 API 都被认为是稳定的并且可供生产使用。我们在主要版本中保持稳定功能的向后兼容性。

    ### 测试版功能

    文档中标记为 `beta` 的功能包括：

    * 功能完整并经过测试
    * 对于生产使用是安全的，但了解它们可能会改变
    * 根据用户反馈，API 可能会进行细微调整

    ### 实验特性

    标记为 `experimental` 或 `alpha` 的功能：

    * 正在积极开发中
    * 可能会发生重大变化或被删除
    * 生产中应谨慎使用

    ### 内部 API

    以下划线前缀 (`_`) 或明确标记为内部的 API：

    * 不属于公共 API 的一部分
    * 可能会更改，恕不另行通知
    * 不宜直接使用

    ## 弃用政策

    弃用功能时：1. **弃用通知**：功能被标记为已弃用，并有明确的迁移指南
    2. **宽限期**：已弃用的功能在至少一个次要版本中仍然有效
    3. **删除**：仅在主要版本发布中删除功能
    4. **迁移支持**：我们提供迁移指南，并在可能的情况下提供自动化工具

    ## 平台兼容性

    ### JavaScript/TypeScript 支持

    * 我们支持 Node.js LTS 版本
    * 为所有公共 API 提供 TypeScript 定义
    * 记录了客户端组件的浏览器兼容性

    ## 重大变更

    重大更改仅在主要版本中引入，包括：

    * 删除已弃用的 API
    * 所需参数的更改
    * 影响现有应用程序的默认行为的更改
    * 最低 Python/Node.js 版本更新

    ## 迁移支持

    对于大版本升级，我们提供：

    * 全面的迁移指南
    * 可行时自动迁移脚本
    * 延长对先前主要版本的支持期
    * 清晰记录所有重大变更

    ## 长期支持 (LTS)LangGraph遵循长期支持（LTS）政策，为生产应用程序提供稳定性：

    ### 发布状态定义

    包裹标记有以下状态之一：

    * **ACTIVE**：当前正在积极开发，包括错误修复、安全补丁和新功能
    * **维护**：接收所有安全补丁和关键错误修复，但没有新功能

    ### 当前 LTS 版本

    **LangGraph 1.0** 被指定为 LTS 版本：

    * **状态**：2.0 发布之前一直有效
    * **支持期限**：2.0发布后，1.0将进入MAINTENANCE模式至少1年
    * **Semver 合规性**：用户可以在次要版本（例如 1.0 到 1.1）之间升级，而无需进行重大更改

    ### 旧版本支持

    **LangGraph 0.4**：

    * **状态**：维护模式
    * **支持期**：截至 2026 年 12 月
    * **支持包括**：所有安全补丁和关键错误修复
